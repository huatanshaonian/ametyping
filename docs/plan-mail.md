# 计划：Windose 接入中国科技网邮箱（收件总结 / 重要提醒 / 发件）

状态：2026-10-02 开工，分支 `feature/mail`。

## 1. 需求（用户提出）

- 用户工作用中国科技网（中科院邮件系统）邮箱，**两个邮箱**都要接进来。
- 把邮件读出来，**每天做总结**。
- **注意重要信息，避免错过**。
- 最好能**发件**。

## 2. 调研结论：可行

中科院邮件系统（Coremail）支持标准 IMAP / SMTP，不需要官方 API。

| 用途 | 服务器 | 端口 | 加密 |
|---|---|---|---|
| 收件 IMAP | `mail.cstnet.cn` | 993 或 996 | SSL |
| 发件 SMTP | `mail.cstnet.cn` | 465 或 994 | SSL |
| 收件 POP3（不用） | `mail.cstnet.cn` | 995 | SSL |

- **用户名**：完整邮箱地址。
- **密码**：邮箱绑定手机号后，第三方客户端必须用「客户端专用密码」。
  - 生成：网页邮箱 → 设置 → 邮箱密码 → 「+」→ 短信验证 → 起名，得到专用密码。
  - 两个邮箱各生成一个。可随时单独作废，不影响网页登录。
- **群晖可直连**：2026-10-01 从群晖测试 `mail.cstnet.cn:993` 与 `:465` 的 TLS 握手均成功（证书 DigiCert / GeoTrust）。国内服务器，**不走 egress 代理**。

参考：

- https://help.cstnet.cn/changjianwenti/youjianshoufa/xitongcanshu.html
- https://help.cstnet.cn/khd-2021.pdf

## 3. 设计

### 3.1 文件划分

新模块 `remote/server/mail/`，按功能分文件：

- **`accounts.js`**：账号增删改。
  - 存在 `data/mail.json`，权限 600。
  - 字段：邮箱地址、显示名、IMAP / SMTP 主机与端口、专用密码、各文件夹已读到的 UID。
  - 接口不返回密码。
- **`imap.js`**：收件。
  - 每个账号一条长连接，优先用 IMAP IDLE，断线重连；不支持时每 5 分钟轮询。
  - 只抓新邮件：按 UID 增量拉取，记录 `UIDVALIDITY`，变了就重建索引。
  - 一律用 `BODY.PEEK`，**不把邮件标成已读**。
  - 默认只看收件箱；其他文件夹按需加。
- **`store.js`**：邮件存档，写到 `data/mail/<账号>/<日期>.jsonl`。
  - 每封存：Message-ID、UID、发件人、收件人 / 抄送、主题、时间、纯文本正文（截断到合理长度）、附件名与大小、是否直接发给我。
  - HTML 邮件转纯文本；GBK / GB18030 等编码由 mailparser 转成 UTF-8。
  - 附件本体不存。
- **`triage.js`**：判断重要性，分两层。
  - **规则**：
    - 重要联系人名单（用户维护）；
    - 是否直接发给我（区分收件人 / 抄送 / 群发 / 邮件列表，看 `List-Id`、`Precedence: bulk` 等）；
    - 关键词：截止、报销、经费、审批、会议、答辩、评审、deadline……
  - **模型复核**：是否需要我行动、截止时间、一句话摘要。
- **`digest.js`**：每日邮件总结。
  - 沿用 `server/summary/codex.js` 的 `runCodex`。
  - 分三类：需要处理 / 回复、通知类、可忽略。
  - 与工作日报合并还是单独成「邮件日报」，待定。
- **`smtp.js`**：发件。
  - 写信、回复：回复时带 `In-Reply-To` / `References`。
  - 发出后用 IMAP `APPEND` 存一份到「已发送」，网页邮箱和手机上都能看到。
- **`index.js`**：路由与对外接口，`server.js` 只做接线。

网页：

- `remote/public/js/apps/mail.js`：邮件窗口，包含账号设置、邮件列表、阅读、写信 / 回复、重要邮件。
- 另配 `remote/public/css/mail.css`。

### 3.2 重要邮件提醒

- 判为重要的邮件：
  - Windose 弹窗；
  - 手机振动：沿用新待确认时的振动，音量里可关；
  - 糖糖气泡：经 agent 下发，格式参考 `summary/index.js` 的 `latestNote()`。
- 邮件里的截止事项：
  - 可一键加进「重要计划」；
  - 已连 Google 时，也可写进 Google 日历。
- 当天未处理的重要邮件，在糖糖的早安日报里再提一次。

### 3.3 发件的安全

- **只做「起草 + 用户确认后发送」**，不做自动发信。
  - 模型可以帮忙起草；
  - 真正发送必须在网页里点确认。
- **验证码**：发送、增删账号需要 1 小时内输过验证码，与现有远程操作一致（`auth.isFresh(sess)`，否则返回 `{need:'totp'}`）。
- **审计**：每次发信记入 `audit.log`，只记收件人和主题，不记正文。

### 3.4 依赖

需新增 npm 包：

- `imapflow`：IMAP，支持 IDLE；
- `mailparser`：MIME 解析与编码转换；
- `nodemailer`：SMTP。

手写 MIME 解析在编码、多段、内嵌附件上容易出错，不自己写。

## 4. 风险与注意

- **隐私**：总结和复核要把邮件内容交给 Codex，即发到 OpenAI 的服务器。单位邮件可能有敏感内容或相关规定。
- **服务器风控**：同一 IP 频繁登录可能触发 Coremail 风控。所以：
  - 用长连接 + IDLE，不要每次轮询都重新登录；
  - 登录失败要退避重试，并在窗口里提示，不要反复撞密码导致锁号。
- **专用密码存在群晖上**：文件权限 600，接口不外露。
  - 若泄露，在网页邮箱里作废这一个专用密码即可。
- **大邮件 / 附件**：只抓正文和附件元数据。正文过长时截断，总结只用截断后的内容。
